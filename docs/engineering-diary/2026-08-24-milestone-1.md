## What I am learning

### HTTP

The scanner obtains public source content over HTTP. A successful HTTP request is not enough: the returned HTML must also contain the structure we expect.

### HTML / DOM parsing

The STM page currently exposes funding calls as expandable button headings. The parser uses semantic button elements and avoids relying on visual colour such as the blue background described by the stakeholder.

### Python

Functions normalize text, generate a stable fallback key, parse HTML, construct validated models, and perform asynchronous HTTP requests.

### Pydantic / schemas

`FundingCallCandidate` creates a boundary between messy source-specific HTML and the rest of the application. Downstream code should not need to know how STM's HTML works.

### Testing

Parser tests run against a local fixture rather than depending on STM being online. An optional live smoke test can later verify the real source structure.

### CI

GitHub Actions will automatically run linting, static type checks, and tests on backend changes.

## Workplace reasoning

We deliberately did not start with the dashboard, PostgreSQL, SSO, Celery, Redis, or AI. The highest early technical risk is whether external funding information can be extracted reliably and represented consistently.

The parser fails loudly if the expected source structure disappears. Returning an empty successful result could incorrectly imply that all funding calls vanished.

## Data-engineering connection

This is the beginning of the extraction and normalization stages of an ETL-style pipeline:

`Source -> Extract -> Normalize/Validate -> [next: Persist]`

The stable `external_key` is also preparation for idempotent ingestion and deduplication.

## Interview story being created

Possible question:

**How did you design ingestion from several external systems with different structures?**

Current answer foundation:

"I introduced a source-adapter boundary. Each portal owns its extraction logic, but every adapter emits the same validated canonical funding-call model. This isolates source layout changes from downstream database, notification, and reporting logic. I also added structural validation so a broken parser fails visibly rather than silently producing incorrect data."
